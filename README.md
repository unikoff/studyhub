# StudyHub Planner

StudyHub Planner — консольный менеджер личных задач. Он помогает добавлять задачи с приоритетом, искать их, отмечать выполненными и смотреть статистику. Данные сохраняются локально в JSON.

## Требования

- Python 3.12 (проект проверяется на Python 3.12.10).
- Git для клонирования.
- Для запуска приложения сторонние пакеты не нужны. Для проверок используется pytest из `requirements-dev.txt`.

## Клонирование и подготовка в Windows PowerShell

Выполняйте команды из каталога, где хотите разместить проект:

```powershell
git clone https://github.com/unikoff/studyhub.git
Set-Location studyhub
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Окружение можно не активировать: далее используется его `python.exe` напрямую.

## Проверки и запуск

Запустите проверки из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m app.main
```

При первом запуске отсутствие `data/tasks.json` означает пустой список. Успешное добавление, первое завершение и удаление сохраняют новый полный снимок. Обычный пользовательский путь выполняется через меню:

- `add` — добавить задачу; введите непустое название и приоритет от 1 до 5.
- `list` — показать сохранённые задачи.
- `find` — найти задачу по положительному целому id.
- `done` — отметить задачу выполненной.
- `delete` — удалить задачу по id.
- `search` — искать по непустому фрагменту названия.
- `stats` — показать число всех, выполненных и открытых задач и процент выполнения.
- `exit` — завершить приложение.

Для проверки сохранения между процессами можно пройти контрольный путь:

1. В первом запуске выберите `add`, введите `Проверка сохранения` и приоритет `3`; затем выберите `done` и введите показанный id, после чего введите `exit`.
2. Запустите приложение ещё раз командой `.\.venv\Scripts\python.exe -m app.main`. Команды `list` и `stats` покажут ту же задачу в выполненном статусе.
3. Файл `data/tasks.json` создаётся в этой копии проекта и не добавляется в Git.

Повреждённый или недоступный JSON не считается пустым списком: приложение сообщает об ошибке хранения и останавливает текущий запуск. Подробности связей компонентов приведены в [docs/architecture.md](docs/architecture.md), а назначение имеющихся автоматических проверок — в [docs/test-matrix.md](docs/test-matrix.md).

## Архитектура и ограничения

`Task` проверяет правила одной задачи и управляет её статусом. `PlannerService` координирует операции через переданное хранилище. `JsonStorage` сохраняет задачи между запусками; `MemoryStorage` хранит состояние в текущем процессе и удобен для изоляции проверок. CLI обрабатывает команды и показывает результаты, а `app.main` собирает рабочие зависимости.

`JsonStorage` записывает полный JSON-снимок; транзакций, атомарной замены файла и координации конкурентных процессов нет. Не запускайте несколько экземпляров для записи в один файл одновременно. Личные задачи находятся в локальном `data/tasks.json`, который игнорируется Git.
