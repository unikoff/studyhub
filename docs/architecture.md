# Архитектура StudyHub Planner

## Путь команды и данных

```text
Пользователь
    ↓ ввод / сообщения
CLI: run → execute_command → обработчик
    ↓ вызов прикладной операции
PlannerService
    ↓ load / save
Storage contract
    ├── JsonStorage: JSON-файл между запусками
    └── MemoryStorage: состояние в памяти процесса
             ↓
          Task: правила одной задачи
```

`app.main` является точкой сборки: он создаёт `JsonStorage` для `data/tasks.json`, передаёт его в `PlannerService` и запускает CLI. Импорт `app.main` не запускает меню.

## Ответственность компонентов

- **`Task` (`app/models.py`)** — проверяет id, название, приоритет, статус и tags; меняет состояние одной задачи. Она не читает файлы.
- **`PlannerService` (`app/services.py`)** — выполняет операции add/list/find/search/done/delete/statistics через переданный storage. Он не знает о терминальном вводе и JSON-пути.
- **Storage (`app/storage.py`)** — предоставляет общий договор `load()`/`save(tasks)`. `JsonStorage` преобразует записи JSON в Task и обратно. `MemoryStorage` нужен для сценариев одного процесса. Обёртка в тестах может наблюдать вызовы через композицию, не создавая второй список.
- **CLI (`app/cli.py`)** — читает и нормализует команду, передаёт `read`/`write` и показывает результат сервиса. Предметные изменения и файловый ввод-вывод остаются в своих слоях.
- **`app.main`** — выбирает рабочий storage и переводит `StorageError` в сообщение о завершении приложения.

Зависимость от storage передаётся при создании сервиса. Это позволяет подставить `MemoryStorage` вместо `JsonStorage` в проверке, сохранив прикладные операции.

## Ошибки и ограничения

Неверный ввод обрабатывается на границе CLI; неизвестная задача представлена `TaskNotFoundError`; ошибки чтения или записи представлены `StorageError` и не превращаются в пустой список. Отсутствующий файл при первом запуске означает пустое начальное состояние.

При успешном изменении `JsonStorage` сериализует и записывает полный снимок. Запись не транзакционная и не атомарная; при сбое записи нельзя обещать откат уже изменённого объекта в памяти. Одновременные писатели не координируются. Эти пределы приемлемы для учебного локального CLI и должны учитываться при расширении проекта.
