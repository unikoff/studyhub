# Краткий план защиты проекта (5 минут)

1. **Назначение и путь одной задачи (около минуты).** Добавление начинается в CLI. Команда вызывает `PlannerService`, сервис создаёт `Task` и передаёт список в storage; CLI показывает результат.
2. **Границы ответственности (около минуты).** `Task` владеет правилами одной задачи, сервис — прикладными операциями, storage — чтением и сохранением, CLI — вводом и сообщениями, `main` — сборкой зависимостей.
3. **Проверки (около минуты).** CLI-регрессии проверяют команды, ответы и число `save`; integration-тест проходит через новый сервис и временный JSON; пользовательский JSON не используется.
4. **Восстановление (около минуты).** Закрыть приложение, создать новый сервис на том же пути и показать восстановленные id/статус. Неизвестный id и повреждённый JSON должны давать разные ожидаемые ошибки.
5. **Компромиссы и запуск (около минуты).** README содержит команды установки, тестов и запуска. JSON хранит полный снимок, не предоставляет транзакций или защиты одновременной записи. Принятую версию сверять через `git rev-parse HEAD`.
